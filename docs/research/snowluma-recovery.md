# SnowLuma sending and disconnection recovery boundaries

Reviewed: 2026-10-27. This records inspection of official documentation and relevant source paths; no live QQ integration was tested. “No guarantee found” does not mean the capability is absent from every version.

- A successful `send_group_msg` result contains a `message_id`, and `get_msg` can look up a message by a known ID. The latter cannot replace confirmation of a send by client request ID. [Send API](https://snowluma.github.io/en/docs/api/message/send_group_msg), [message lookup](https://snowluma.github.io/en/docs/api/message/get_msg)
- The server dispatch path inspected executes the action before attaching `echo`; the SDK uses `echo` to associate pending requests in memory. No guarantee of a persistent idempotency key or recovery of a result by client request ID was found in the send parameters or these implementation paths. [Server dispatch](https://github.com/SnowLuma/SnowLuma/blob/main/packages/onebot/src/api-handler.ts), [SDK WebSocket client](https://github.com/SnowLuma/SnowLuma/blob/main/packages/sdk/src/client/websocket-client.ts)
- The SDK fails pending requests on disconnection. Automatic reconnection does not mean actions are resent, and a timeout or cancellation cannot prove that the remote side did not execute an action. [SDK implementation](https://github.com/SnowLuma/SnowLuma/blob/main/packages/sdk/src/client/websocket-client.ts), [MCP safety boundaries](https://snowluma.github.io/en/docs/mcp#safety-boundaries)
- The ordinary WebSocket path inspected did not guarantee complete replay of events missed during disconnection. Group message history can be queried separately, but it is not a complete history of events such as pokes, recalls, and emoji reactions. Login history synchronization also has scope limits and does not imply complete event recovery on every client reconnection. [WebSocket server](https://github.com/SnowLuma/SnowLuma/blob/main/packages/onebot/src/network/ws-server-connections.ts), [group message history](https://snowluma.github.io/en/docs/api/extended/get_group_msg_history), [login history synchronization](https://github.com/SnowLuma/SnowLuma/blob/main/packages/onebot/src/history-sync.ts), [notice conversion](https://github.com/SnowLuma/SnowLuma/blob/main/packages/onebot/src/event-converter/to-notice.ts)

Subsequent interviews confirmed that received events are saved and understood in batches, unrecoverable history is recorded as a perception gap, and the Agent reassesses expired activities. When an action outcome is unknown, it first attempts verification; if confirmation is impossible, it retains the unknown state and does not automatically retry blindly. The decisions are recorded in [ADR-0007](../adr/0007-delayed-perception-and-explicit-recovery-gaps.md) and [ADR-0008](../adr/0008-preserve-unknown-action-outcomes.md), respectively. They do not promise exactly-once sending or lossless recovery of all events during disconnection.
