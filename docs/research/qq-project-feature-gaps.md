# Feature differences among qq-bridge, Aurabot, and Qiuyue

Reviewed: 2026-11-03. This comparison uses implementations in the reference projects' default-branch source at the revisions below. Neither reference project was deployed or run. An implementation still depends on account, platform, model, dependency, and configuration requirements. This compares product capabilities, not apparent humanity or model quality.

Status: historical comparison. External-project findings retain the snapshots below. On 2026-11-04, Qiuyue's status was updated for user-plugin loading and reload. A further repository review on the same date identified three superseding changes: the persistent [gallery](../adr/0018-draw-apart-from-the-thought-and-send-drawings-by-their-id.md), optional [Bilibili and Xiaohongshu plugins](../online-life.md), and native [SnowLuma and Telegram adapters](../platform-adapters.md) under [ADR-0022](../adr/0022-expose-complete-native-tools-through-platform-adapters.md). Relevant rows distinguish the original gap from this later implementation. Other historical differences remain subject to the current README and ADRs; this is not a feature backlog.

Evaluation principle: preserve the model's freedom to judge and express itself. The program supplies capabilities, keeps state, and executes explicitly selected actions. Automatic sentence splitting, fixed mood increments, drives that grow over time, and score-determined behavior are not recommended additions. The mood and drive differences below refer to dedicated mechanisms in the other projects. Qiuyue's existing notes, understanding, habits, impressions, pursuits, and continuing working context can already carry much of this content; their absence as separate mechanisms does not establish an absence of emotions, intentions, or continuing goals.

## Capabilities absent from the original Qiuyue snapshot

The Qiuyue column describes the reviewed snapshot unless explicitly marked as a 2026-11-04 update. Local source links follow the current checkout.

| Capability | Reference implementation | Qiuyue boundary and subsequent changes |
| --- | --- | --- |
| Continuing mood linked to behavior | Aurabot persists mood, reasons, and history; returns toward a baseline over time; updates through keywords or optional model judgment; and affects voice, stickers, participation probability, and send intervals. [Mood implementation][a-mood] | Feelings can enter working context, memory, and activities, but there was no dedicated mood state, decay mechanism, or delivery-layer integration. [Continuing state](../../src/domain.ts), [tools](../../src/tools.ts) |
| Internal drives and goal hypotheses | Aurabot's experimental purpose engine stores nine drives, including play, learning, contact, care, sharing, and creation, which change with time and evidence. Goals retain ownership, evidence, confidence, value, urgency, and risk, and are revised from owner feedback. The module defaults off. [Drives and goals][a-purpose-engine], [persistence and wiring][a-purpose-module] | Activities, pursuits across days, commitments, self-directed wake-ups, and rest already existed. The missing parts were this specific drive dynamics and goal-hypothesis feedback structure; that does not mean Qiuyue cannot live proactively. [Tools](../../src/tools.ts), [domain structures](../../src/domain.ts) |
| Custom-voice speech pipeline | Aurabot integrates TTS, local synthesis endpoints, optional RVC conversion, DSH local speech-recognition adaptation, and panel testing. [Voice module][a-voice] | Native QQ `fetch_ptt_text`, `get_ai_record`, `send_group_ai_record`, and record-message sending already existed, without a dedicated TTS voice, RVC conversion, or local ASR pipeline. It requires the module, a voice, and runtime setup; the reviewed cover pipeline targets Windows. [Song module][a-song], [studio implementation][a-song-studio] | A pursuit can retain an intention to learn a song, but there was no pipeline generating sung audio. [Pursuit tools](../../src/tools.ts) |

[Bilibili module][a-bili], [activity loop][a-bili-duty] | The original snapshot had web search, reading, and image viewing without a Bilibili adapter. **2026-11-05 update:** an optional user plugin now provides discovery, subtitle/content and comment reading, reading history, native favorites, and likes/unlikes with remote-state verification. [Online life](../online-life.md), [plugin source](../../packages/bilibili/) |

Those materials do not establish full audiovisual understanding. A browser environment is required. [Douyin module][a-douyin], [browsing loop][a-douyin-duty] | There was no corresponding platform module or browser automation capability. A separately installed read-only Tieba extension supports search, browsing, reading, and scheduled browsing, without posting or replying. [Heybox module][a-heybox], [Tieba extension][a-tieba] | No account integration, dedicated reading/writing tools, or activity loop for these platforms was present. It is implemented, not merely planned in the README. [Module list][a-module-list], [pet implementation][a-pet] | The original interaction channel was QQ, with CLI/TUI/WebUI management and no character desktop client. **2026-11-04 update:** native adapters also support Telegram, so QQ is no longer the only interaction platform; a desktop character client remains a separate capability. ## Existing foundations with more specialized reference mechanisms

| Area | Difference and assessment |
| --- | --- |
| User-plugin loading and reload | Aurabot supports user-module directories, replacement by the same ID, and automatic change detection. As of 2026-11-04, Qiuyue supports `plugins/<id>/`, a versioned SDK, and explicit reload without modifying the built-in registry or restarting the daemon. It does not watch code changes automatically or permit overriding built-in plugin IDs. A failed load retains the old instance, and switching occurs at a controlled boundary. This is a runtime-policy difference, no longer a missing capability. [Plugin documentation](../plugins.md), [ADR-0021](../adr/0021-reload-scoped-plugins-between-thoughts.md), [Aurabot module core][a-modules] |
| Chat bubbles and pacing | Aurabot parses replies, cleans formatting, splits bubbles, sets intervals from length and mood, and automatically sends private-chat typing status. qq-bridge offers `qq_send_burst` with randomized intervals. Qiuyue can choose separate messages and has native `set_input_status`, without those automatic delivery mechanisms. Any benefit from waiting should be evaluated alongside existing interruption of stale replies. [Aurabot delivery][a-hub], [interval formula][a-reply], [qq-bridge bursts][q-burst], [Qiuyue interruption](../adr/0002-single-attention-with-continuous-perception.md) |
| Image-generation integration and artwork management | Besides OpenAI-compatible generation, Aurabot provides custom GET/POST requests, parameter templates and result paths, local generation endpoints, composition dimensions, and a management gallery. Qiuyue already had asynchronous generation, viewing its own results, sending/Qzone/sticker reuse, and persistence; generation requests sent only the model and description. **2026-11-04 update:** Qiuyue now has a persistent gallery, search/view/organization tools, and a management panel under ADR-0018. The earlier missing-gallery claim is superseded; the endpoint-option differences remain. Image-to-image generation or editing in Aurabot was not confirmed, and the name `qq_edit_sticker` alone does not establish image editing. [Aurabot generation][a-image], [generation tools and gallery][a-image-module], [Qiuyue generation](../../src/plugins/drawing.ts), [ADR-0018](../adr/0018-draw-apart-from-the-thought-and-send-drawings-by-their-id.md) |
| Conditional lurking and wake-up | qq-bridge's second-generation simulation supports wake conditions for speakers, keywords, names, questions, pokes, ordinary-message probabilities, and observation windows. Qiuyue already had self-directed timed wakes and rest, retained group messages while resting, and participated when mentioned, replied to, or poked, without the same detailed Agent-set condition table. It is incorrect to describe lurking or waking as wholly absent. [Condition tools][q-wake], [Qiuyue rest](../adr/0016-hold-group-chat-while-resting.md) |
| Chinese retrieval and retention | Aurabot uses Chinese bigrams, BM25, the preceding message for short inputs, and recall-dependent retention. Qiuyue already had FTS5 trigram, text-match ranking, per-line embeddings, spontaneous recall, and RRF for deliberate search. This is not a difference between having and lacking memory, and no controlled data establishes that Aurabot's retrieval is better overall. [Aurabot memory][a-memory], [Qiuyue text retrieval](../../src/store.ts), [semantic retrieval](../../src/recall.ts) |

## Differences that require a project-direction decision

- **Different models by group or private chat.** Aurabot can choose a model and reasoning level for individual contacts, groups, and private/group defaults. Qiuyue uses one primary-model configuration; model selection also contributes to the identity of the continuing working context. Routing by setting would first require deciding how to preserve one subject and context continuity, rather than copying separate session structures. [Model routing][a-chat-model], [one-subject ADR](../adr/0001-one-agent-across-group-environments.md), [context design](../adr/0017-tell-the-working-context-each-thing-once.md)
- **A remote personal assistant and approvals over QQ.** qq-bridge's `closed-agent` exposes DSH's full local tools only to administrator private chats, forwards DSH questions/approvals to QQ, and handles administrator replies. It also has four operating modes, character cards, and QQ management commands. Qiuyue has no remote local-tool assistant, QQ approval relay, or those modes; its runtime control uses a local management surface, separate from ordinary social requests. Treating ordinary QQ messages as pause or persona-switch commands would change the management boundary and require revisiting ADR-0003, rather than being a routine missing feature. [Modes and commands][q-rules], [approval handling][q-approval], [management boundary](../adr/0003-separate-runtime-control-from-social-requests.md)
- **Conversation-level receive/send allowlists and permissions.** qq-bridge does not respond when its default allowlist is empty and checks send targets. Aurabot also has contact and permission modules. Qiuyue supports native-interface allow/deny rules and runtime budgets, but live perception is not restricted by `snowluma.groups`, which serves history recovery. Participation scope or action permissions by person/group must be designed separately from the choice to perceive continuously. [qq-bridge boundaries][q-rules], [Qiuyue perception](../adr/0011-perceive-all-snowluma-push-events.md), [interface permissions](../adr/0010-expose-native-snowluma-actions.md)

## Existing capabilities that should not be called missing

At the original snapshot, Qiuyue already supported image viewing and sending; QQ system faces, reactions, and pokes; saved stickers with descriptions and semantic suggestions; quoted replies; Qzone browsing, posting, likes, comments, and sharing; QQ profile and status changes; web search and reading; image generation; long-term memory and revision; impressions, habits, and practices; autonomous activities, pursuits, commitments, and rest; and CLI/TUI/WebUI management and model-provider configuration. The native catalog contained 212 interfaces, but declarations do not establish successful account-level verification of every operation. Later adapter coverage is documented separately. [README](../../README.md), [plugin entry point](../../src/plugins/index.ts), [native tools and activities](../../src/plugins/snowluma-tools.ts), [catalog](../../src/snowluma-catalog.ts), [platform adapters](../platform-adapters.md)

Aurabot's introduction mentions a module marketplace. At this revision, source review confirmed user-module directories, module management, and a separate bundled Tieba extension, but did not confirm online marketplace search and installation. This comparison therefore counts user extensions and hot loading, not a marketplace. [Module core][a-modules], [extension directory][a-extensions]

## Historical recommendations for Qiuyue's goals

The original recommendation prioritized media reading, artwork search and reuse, and operator cost visualization, because they add concrete capabilities. **The gallery and optional online-life plugins have since addressed parts of that recommendation; consult their current documentation before planning more work.** GIF frame reading should retain original media and let the model request more frames. A gallery provides access to works without rebuilding memory. Conditional wakes are useful when the model needs to wait for a person or event; the model should choose conditions, expiry, and whether to keep paying attention. That would extend ADR-0016's rest and wake rules and requires explicit semantics. Cost analysis could borrow trends and drill-down, while retaining one subject and grouping by actual use, such as primary thinking, memory consolidation, and context compaction, rather than forcing separate group-session ownership.

Dedicated voices, song covers, and external-platform tools add actual expression or action capabilities. Their priority depends on the desired scope of life. Once tools exist, Qiuyue decides when to use them. Generated content can return through the established asynchronous image-generation pattern, with the same subject choosing subsequent actions. User-plugin loading and explicit reload are implemented; lifecycle and tool-set changes follow ADR-0021. Automatic watching would be a separate decision.

This later comparison does not recommend a separate emotion or drive system yet. First use actual runtime records to determine whether important current feelings or unacted-on thoughts are lost from existing notes, pursuits, and continuing context. Native separate-message sending and typing status already support pacing; automatic splitting, rewriting, or random waiting need not be added by default. Preserve the constraints on one subject, experience provenance, and actual action outcomes.
