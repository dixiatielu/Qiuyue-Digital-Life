# 外部线上生活

B 站与小红书是同一个秋月可以去逛的地方。两个可选用户插件提供发现、阅读、阅读历史和平台原生收藏；空闲时是否使用、记住什么、是否与别人分享，仍由主要思考过程决定。没有独立的平台 AI 会话或强制浏览定时器。

## 启用

两个插件的源码分别在 `packages/bilibili/` 和 `packages/xiaohongshu/`，只通过公开 SDK 接入。它们不在核心内置清单里，不安装就不会出现在工具或生活活动中。

先单独构建插件：

```sh
npm run build:plugins
# 也可以只构建一个
npm run build:plugins -- xiaohongshu
```

产物在 `output/plugins/<id>/`，每个目录只需 `index.mjs` 和 `plugin.json`，不依赖源码目录或另外一个平台。将需要的目录复制到 `extensions.directory`（默认是 `config.json` 旁的 `plugins/`）。配置文件在项目根目录时，例如：

```sh
mkdir -p plugins
cp -R output/plugins/bilibili plugins/
cp -R output/plugins/xiaohongshu plugins/
```

首次升级到支持插件清单和 SDK 图片附件的这一版主程序，需要 `npm run build` 并按原有方式重启常驻进程和管理网页一次。此后安装或更新这两个插件只需替换各自的文件并重载，不必改动或重编译主程序。在管理网页「能力与插件」中开启 **B 站** 或 **小红书**，保存后点击对应插件的「重载」。也可以合并以下配置：

```json
{
  "plugins": {
    "bilibili": true,
    "xiaohongshu": false
  },
  "extensions": {
    "settings": {
      "bilibili": {
        "cookieEnv": "BILIBILI_COOKIE"
      },
      "xiaohongshu": {
        "baseUrl": "http://127.0.0.1:18060",
        "tokenEnv": "XIAOHONGSHU_TOKEN"
      }
    }
  }
}
```

```sh
npm run dev -- plugins reload bilibili --config config.json
npm run dev -- plugins reload xiaohongshu --config config.json
```

两者默认关闭，分别控制，不依赖通用网页工具的 `web.enabled`。关闭后工具和生活选项一起撤下，原有阅读历史保留。要让秋月在空闲时自己去逛，还需要原有的自主生活模式开启；开启平台工具本身不会打开自主生活。聊天中遇到链接仍可按当前情境决定是否阅读。

管理页直接读取各插件的 `plugin.json`，无需启动插件即可展示名称、说明、设置与凭据名称。请求超时、请求间隔、每日请求上限和限流后的冷却时间都属于插件配置；校验在加载候选插件时进行，失败保留正在运行的版本。设置与凭据可通过重载生效；工具声明或插件声明的上下文契约变化时才更新工作上下文。

卸载时先关闭并重载该插件，再移走 `plugins/<id>/` 并执行一次对应插件的重载（或 `reload all`）。另一个平台、QQ 和记忆系统继续工作。原有经历和插件存储不会随卸载删除，之后以相同 ID 重装仍可续读。

### B 站

公开内容可先尝试匿名读取。需要登录的内容（例如部分字幕）要在管理页「模型 → 凭据」中设置 `BILIBILI_COOKIE`，然后重载 B 站插件。原生收藏也需要登录，Cookie 必须包含 `SESSDATA` 和 `bili_jct`。`cookieEnv` 填凭据名称，Cookie 值保存在凭据文件或环境变量中，不写入普通配置。

支持 BV/av 号、完整视频链接（包括 `?p=2`）和直接跳到视频的 `b23.tv` 短链。空查询浏览热门视频，不宣称是个性化推荐；带查询时搜索视频，过滤课程等非视频卡片。

每次读取一个分 P 的简介、最多 80 行/约一万字字幕，以及最多 8 条热评。保存的是**字幕阅读位置**，没有模拟播放时长，也没有获取视频帧或音频。字幕读到该 P 末尾后，下次从下一 P 开始。可以用 `restart: true` 从头阅读，或通过链接中的 `p` 选择分 P。字幕不可用、登录缺失或读取失败会明确返回，不视为看完；某一 P 的字幕读完也不表示看过视频的所有部分。

收藏默认使用唯一名为「默认收藏夹」的自建收藏夹，也可以在插件设置的 `favoriteFolderId` 中指定自己的收藏夹 ID。无法明确找到目标时会报错，避免误操作其他收藏夹。取消收藏只从这个收藏夹移除；在其他收藏夹中的收藏不变。

### 小红书

先按 [xpzouying/xiaohongshu-mcp 的说明](https://github.com/xpzouying/xiaohongshu-mcp) 部署并登录服务。这里使用其 HTTP 接口，不要求给模型直接开放 MCP 工具。`baseUrl` 指向服务地址；服务配置了 `AUTH_TOKEN` 时，把相同的值存为 `XIAOHONGSHU_TOKEN`。浏览器登录态由小红书服务维护，秋月不接收其 Cookie。

读取推荐或搜索结果后，插件会私下保留打开笔记所需的 `xsecToken`。模型只需将返回的笔记 ID 交给 `xhs_read`。也可读取带 `xsec_token` 的完整笔记链接；短链暂不支持。过期的访问参数不会反复自动重试，应重新搜索以取得新结果。

一次 `xhs_read` 返回正文、少量评论和实际图片附件，模型在下一轮直接同时看到图文，无需先看地址再调用看图工具。图片通过通用 SDK 的 `call.attachImages` 交给宿主加载，平台插件只提供来自本次阅读来源的 URL。宿主沿用公共图片地址检查，并限制数量（`limits.maxImages`，每次工具调用最多 20 张）、单图 5 MB 和总计 12 MB；图片附件不把 Base64 写入经历记录。

返回的 `imageDelivery.attached`、`failed`、`omitted` 分别说明真正附上的图片、加载失败和因限制未加载的图片。图片失败仍保留正文，未送达的图片不能当作已经看过；必要时仍可用 `view_event_image` 按 `sourceId` 补看。视频和 Live Photo 的动态及声音暂不感知。当前服务只返回一批推荐/搜索结果，插件不伪造下一页。

## 工具与连续性

每个平台有四个工具（前缀分别为 `bili`、`xhs`）：

| 工具 | 行为 |
| --- | --- |
| `*_browse` | 发现内容；可指定自己的查询词。预览不算已经阅读正文 |
| `*_read` | 读取内容并生成带 `sourceId` 的真实经历，更新阅读位置 |
| `*_history` | 查看本地阅读缓存或 `savedOnly: true` 的收藏缓存，包含原阅读来源及进度；不是平台完整收藏列表 |
| `*_keep` | 用 ID 在已登录的平台账号上收藏（`saved: true`）或取消收藏（`saved: false`）；备注只保存在本地 |

发现与阅读使用现有经历记录。阅读位置、上次确认的收藏状态和意图通过 `ctx.storage` 保存在同一 SQLite 的插件专属命名空间中，跨重载、重启保留。历史缓存最多 200 条普通记录和 100 条收藏记录；超出时淘汰较旧缓存，不会取消平台收藏。`platformFavorite` 表示上次确认的状态与时间；在手机等其他客户端的改动不会自动同步到本地列表。旧版本只有 `saved` 而没有 `platformFavorite` 的记录仍是本地书签，升级不会把它们批量上传为平台收藏。`*_history` 是导航数据，个人备注不是新的外部证据；记录中的原始 `sourceId` 仍遵循系统的经历保留策略。

有意义的内容由秋月通过 `remember` 记住，并引用真实阅读来源；跨天想继续做的事使用已有 `update_pursuit`。插件不自动生成偏好，也不把每次浏览都变成长期追求。生活唤醒会看到平台活动及最近实际浏览时间。记忆复盘只能查看平台历史，不能自行刷平台。

QQ 分享继续使用原有消息工具，遵循对象与社交情境。浏览成功不会自动发消息。原生收藏按秋月自己的兴趣选择，会向平台反馈账号行为；具体推荐权重及后续推流由平台决定。当前没有点赞、评论、回复或发布工具，也不模拟视频播放时长。

## 人设与系统提示词

系统提示词只约定通用的感知与动作规则：图文已一起返回时不重复看图，图片地址不等于看过图片，字幕不等于看过视频，账号操作以确认的回执为准。平台工具名、参数和限制由插件说明提供。

`persona.md` 是 Git 忽略的运营者本机配置。可以把下面的线上生活建议放入自己的人设；它们表达兴趣和选择，不要求定时刷平台或汇报：

- 刷 B 站和小红书：可以搜搜最近感兴趣的歌、画画教程、番剧讨论，也可以随便逛逛，遇到没意思的就划过去。今天想看什么由你自己决定，不必为了有日常可聊而刷。
- 收藏和续看：遇到真想回看或继续研究的内容，可以收藏到自己的平台账号，之后从阅读历史找回来接着看；不再感兴趣时也可以取消收藏。收藏是表达自己的兴趣，不必每条都收藏，也不用刻意把推荐养成某个样子。
- 分享发现：看到有趣的东西，正好想起某个熟人或群里聊过的话题，可以带上原链接和一两句自己的感受分享过去。挑合适的人和时机，不必把刷到的东西逐条转发，也不必每次浏览都向别人汇报。

## 请求与失败

每个平台分别限速，默认每日最多 120 个 HTTP 请求，按 UTC 自然日计数。一次阅读可能需要多个请求。默认最小间隔为 B 站 1.5 秒、小红书 3 秒；预算与冷却状态保存在 SQLite，重载不会清零。遇到 HTTP 403/412/429 或已知 B 站风控代码，会冷却 15 分钟；不自动重复请求。

正文请求失败不会创建成功阅读记录，也不会推进进度；图片单独加载失败不会抹去已读正文。简介可读而字幕或评论失败时，保存实际获得的部分，并明确列出不可用内容。请求有超时、响应体大小限制和取消支持。B 站凭据只发到其固定接口，不发送到短链或字幕 CDN；小红书服务鉴权只发到运营者配置的服务，不跟随重定向。

收藏通过 `call.action` 记录操作凭据，使用宿主统一的动作预算与去重。小红书使用服务的幂等收藏／取消收藏接口；B 站先查目标收藏夹状态，无需改变时直接确认，需要改变时提交原生收藏接口并再次检查状态。仅在确认成功后更新本地缓存。已发出的请求若超时或无法确认，记录为 `unknown`，不假定成功、不盲目重发。访问令牌、Cookie 和 CSRF 不进入动作参数或记录。

`test/online-life.test.ts` 覆盖跨重启续读、分 P、非视频搜索卡片、来源、缺失字幕、登录失败、请求预算、冷却、取消、URL 限制和自主生活接入。另覆盖单次图文返回、图片部分失败与数量限制、原生收藏和取消、登录缺失、收藏夹选择、丢失回执及远端状态核验。测试加载的是实际打包产物，覆盖独立安装、单平台重载、候选失败回退、卸载和重装续读，以及没有平台特例的管理页配置与凭据发现。

2026-11-04 已在本机部署并启用两个独立用户插件。B 站匿名实测返回 8 条搜索结果，读取了视频简介与 3 条评论；该样本没有可用字幕，未把它记成已看完。小红书服务 v2.7.2 完成扫码登录，实测返回 10 条搜索结果，读取了笔记正文、8 条评论，并通过 `view_event_image` 取得实际 WebP 图片。两个插件的阅读状态均通过重载验证；小红书服务重启后仍保持登录。验证使用独立数据库，不写入秋月的真实经历库。服务仅绑定本机 18060 端口并开启 Bearer 鉴权，镜像固定到摘要。
