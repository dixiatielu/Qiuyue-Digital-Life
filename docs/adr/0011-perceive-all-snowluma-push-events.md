# Include all SnowLuma push events in unified perception

To let the digital life perceive private chats, friend requests, account status, and other external occurrences, all SnowLuma push events for the current account are persisted rather than filtered by a group list. This supersedes the restriction in [ADR-0010](0010-expose-native-snowluma-actions.md) that group configuration determines continuous perception scope. Messages, feedback on the Agent's own sends, notifications, requests, lifecycle events, and future event types enter the unified observation queue. The same Agent still decides whether to pay attention or act. Raw events retain their sources and social contexts, and API responses continue through the tool receipt flow.

`snowluma.groups` specifies only the groups whose message history should be checked when a connection is established or recovered, and may be empty. It does not limit real-time perception or tool call targets. Observations remain subject to deduplication, batching, pause, and model call budgets. Private chats, requests, notifications, and other events missed during a disconnection are not guaranteed to be recovered; a connection-level perception gap is recorded even when there are no groups to check.

Revision of 2026-10-28: heartbeats repeatedly triggered thinking without social changes and appended large state snapshots. They are now stored only as connection information: they do not wake or steer the model, occupy the recent-experience recall list, or advance the event count for memory consolidation. Pending heartbeats left by older versions are also consumed on restart. Lifecycle and disconnect/recovery events continue to trigger observations; raw heartbeats can still be retrieved by event ID when needed.
