# Expose native SnowLuma APIs

A later change to perception scope is described in [ADR-0011](0011-perceive-all-snowluma-push-events.md): the restriction below that group configuration determines continuous perception scope has been removed; group configuration is used only for historical recovery. One tool outside the SnowLuma catalog, which shares Qzone posts by combining SnowLuma's own interfaces, is described in [ADR-0013](0013-share-qzone-posts-through-qzone-share-service.md).

The digital life autonomously combines actions using SnowLuma's native API names, parameters, and business results. An atomic tool catalog is generated from a fixed version of the official definitions and uses the original API names directly. The catalog filters upstream compatibility placeholder APIs, dotted APIs, historical misspellings, and compatibility field declarations; streaming APIs retain ordered data frames. All enabled APIs are provided directly to the model with their original names and complete parameters. Common APIs retain full descriptions, while the rest have short descriptions to reduce context use. `search_snowluma_tools` searches the catalog, and `load_snowluma_tools` returns detailed usage, parameters, results, and examples without changing the available tool set.

The operator configures API permissions with allow/deny rules, including a fully open mode. Group configuration determines continuous perception and disconnection recovery scope; API call targets are determined by native parameters and can include other groups, private chats, spaces, group management, credentials, and SnowLuma service management. See [ADR-0003](0003-separate-runtime-control-from-social-requests.md) for this project's runtime management boundary.

The unified execution module continues to handle pause and generation checks, provenance, action budgets, and recording actual results. The runtime generates action keys and deduplicates by native API and parameters, following the unknown-outcome semantics of [ADR-0008](0008-preserve-unknown-action-outcomes.md); a receiving limit is not evidence that a retry is safe. The catalog describes the fixed SDK's API scope; actual support, placeholder behavior, and permissions depend on the server.

Revision of 2026-11-04: the generated catalog is a local dependency under `.qiuyue-cache/snowluma/`, prepared with its upstream license and excluded from tracked source and build output. `QIUYUE_SNOWLUMA_CATALOG` can select an existing catalog elsewhere. Native names, schemas, filtering, and runtime permission checks stay the same. The repository's MIT license does not cover the upstream definitions or SDK. The official SDK is consumed as an npm dependency, and SnowLuma is installed separately by the operator; copying or distributing upstream material must follow its own terms. This dependency arrangement is not a determination that ordinary SDK use is a derivative project requiring additional authorization. See [third-party licensing](../../THIRD_PARTY_NOTICES.md).

Revision of 2026-11-02: `add_custom_face` takes an optional `desc` beyond its native parameters. QQ gives a saved sticker its `emoji_id` only when the save returns, so describing it with `modify_custom_face` always took a model call of its own: in the 48 hours before 2026-11-02 13:00, 46 of 48 `modify_custom_face` calls opened a new model call, at a median of about 15 seconds each. The ID looks predictable, as `<account>_0_0_0_<MD5>_0_0`, but the MD5 that a received image is named by matched it for only 166 of 181 saves, so the digital life is not asked to construct it. With `desc`, the save is sent with its native parameters alone, and once it succeeds the runtime sets the description through `modify_custom_face` with the ID it returned. That description is recorded and deduplicated as an action of its own, following [ADR-0008](0008-preserve-unknown-action-outcomes.md), and its outcome is reported with the save's result; a description that failed or whose outcome is unknown leaves the save standing. A sticker QQ already held keeps the description it has, since overwriting one by accident was the harm of saving a sticker twice. `desc` is offered only while `modify_custom_face` is enabled, and `load_snowluma_tools` shows it among the parameters. Like `share_qzone_feed` ([ADR-0013](0013-share-qzone-posts-through-qzone-share-service.md)), this departs from offering native interfaces only with their native parameters, and it should give way if SnowLuma lets a save carry its description.
