# Load seldom-used tools on demand where the model's API can

[ADR-0010](0010-expose-native-snowluma-actions.md) and [ADR-0022](0022-expose-complete-native-tools-through-platform-adapters.md) give the model every enabled native operation with its complete parameters in every call, and each adapter adds a whole catalog. On 2026-11-23 the working context declared 245 tools in about 116,000 characters, measured at 32,400 tokens by gemini-4-hydrogen. In the 30 days before, the 194 SnowLuma operations outside the plugin's `common` set together took 232 of 4,232 native calls, and 163 of them were not called at all. Over the last 7 of those days there were 4,331 model calls averaging 242,000 prompt tokens.

A plugin now marks a tool it expects to be used seldom, and each model request names the marked tools that are currently enabled. A transport whose API loads tools on demand declares those as deferred: the model sees the name and description, and reads the parameters when it decides to use the tool. Every other transport declares them in full, as before. A deferred tool is still declared with its original name and complete parameters, is called exactly like any other, and passes the same permission checks, action ledger, and outcome rules ([ADR-0008](0008-preserve-unknown-action-outcomes.md)). Deferral is not a permission: the operator's allow and deny rules alone decide what is enabled ([ADR-0003](0003-separate-runtime-control-from-social-requests.md)), and loading a tool neither unlocks anything nor records an action. What this revises in ADR-0010 and ADR-0022 is only that every call carries every parameter schema. SnowLuma defers the operations outside `common`. An external adapter defers nothing unless it names its `frequent` operations, and then defers the rest. `search_snowluma_tools`, `load_snowluma_tools`, and `describe_api` still describe tools without changing which are available.

The first such transport is Gemini's Interactions API, which Pi 1.6.0 has no transport for, so the program carries its own (`google-interactions`). Requests are stateless: the working context stays the program's, which compacts, rolls back, and restores it ([ADR-0004](0004-persist-continuity-beyond-model-context.md)), and each request replays the steps the API returned. Thoughts and tool-search steps have no place in Pi's message content, so each is carried whole in a thinking block. Thinking blocks stay in the running process and are left out of the saved context, as they already were.

Measured against gemini-4-hydrogen through the operator's gateway on 2026-11-23: the 232 built-in tools took 26,400 tokens declared in full and 12,800 with the 194 deferred; a tool loaded once is called again in later thoughts without another search; the cached prefix holds across a load. Within the current turn the API takes back only the exact steps it sent, thought signatures included. It refuses a call to a deferred function unless the search that loaded it is still in the history, and a model that has seen itself call a tool does not search for it again. So a request declares in full any deferred tool that its history calls without that search before it. This happens after a restart and after compaction, where the cached prefix is rebuilt anyway.

These models cannot turn thinking off, and gemini-4-hydrogen refuses the `minimal` level, so a request that asks for no thinking, as a summary does, asks for `low`.

Loading has a cost of its own. The API reads the prompt once more for each search, and the gateway billed that reading at the full input price even with a warm cache: at a 29,000-token prompt a loading request cost 0.356 against 0.041 for a cached one. The context is measured from one reading of the prompt, so the further readings are reported apart from it, as `toolUse` and `toolUseCacheRead` in a request's usage. Whether deferral pays therefore depends on how seldom the deferred tools are loaded; the `common` set and an adapter's `frequent` list are where that is tuned. Returning to `google-generative-ai` for the same model declares everything in full again and needs no other change.

Considered and set aside: a host tool that loads declarations by changing the request's tool list, which Gemini's `generateContent` cannot do without replacing the top-level list and with it the cached prefix; and a single dispatching tool that calls operations by name, which would hide the tool name from the hooks that end a thought, find a call's chat, decorate a tool, and deduplicate an action.
