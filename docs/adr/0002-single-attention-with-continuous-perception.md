# Maintain one primary thinking process while continuously receiving environment events

To give the digital life a consistent current activity and attention across group chats, only one primary thinking process advances at a time. It decides whether to continue, shift attention, or set new matters aside; event reception and already-started tool tasks may continue. All environment events enter one perception pipeline and may be combined into observations for joint understanding, avoiding the fragmentation of a coherent group conversation into independent question-and-answer exchanges. The digital life still decides whether to pay attention or respond; mentions and pokes do not automatically create an obligation to reply.

Ordinary environment events intervene at the thinking boundary after the current model call and its tool batch finish, and the same Agent decides whether to adjust or end the current activity. Explicit controls such as administrative stops and timeouts may attempt to cancel the current call. This boundary follows Pi's distinction between ordinary steering and a separate cancellation mechanism, avoiding automatic termination of an ongoing model call for every group event.

Technical reference: [Pi Agent Core — Steering and Follow-up](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md#steering-and-follow-up), checked 2026-10-27. Verify these semantics when integrating a specific version.

Revision of 2026-10-28: two clarifications about when events reach the thinking process. A new thinking run waits until no event has arrived for `limits.debounceMs`, and never waits longer than `limits.maxDelayMs` after the first waiting event, so a burst of messages is understood as one observation; steering into an ongoing run is not delayed. Working-context compaction may also run between runs once the context exceeds `compaction.idleRatio` of its budget. This idle compaction is housekeeping, not a thinking process: any event that can wake thinking cancels it, the working context stays as it was, and the following run compacts at its own boundary only if the full budget requires it. Ordinary events still do not cancel a model call made for thinking.

Revision of 2026-10-29: the first model request of a run now compacts once the context exceeds `compaction.idleRatio` of its budget, replacing "only if the full budget requires it" above. In a busy group, arriving events cancel idle compaction before it finishes, so runs started near the full budget and compacted mid-run after a backlog had been steered in; by then the history was too large to summarize in one request, and every retry failed the same way while events waited. Compacting at the first request leaves room for the observations steered in after it. Later requests in the run still compact only at the full budget, and a first request that cannot make room goes on within the full budget. When no summary can be written, older exchanges are set aside under a note instead of failing the run; their originals stay archived and readable, as [ADR-0004](0004-persist-continuity-beyond-model-context.md) requires.

Second revision of 2026-10-29: a message addressed to the digital life in a conversation its current thought is engaged in now stops that thought at the earliest safe point instead of waiting for the boundary. In a private chat on 2026-10-29, model calls took 9–37 s while the other person wrote every 6–18 s. Three of the six messages the digital life sent there went out after that person had already said something newer. Those lines had been steered in, but they could only enter after the call that was deciding the reply, and the reply was then sent as decided. Steering at the boundary leaves each decision as stale as the remainder of the running call, and still carries it out.

A thought is engaged in a conversation once it has acted there or was started by an event there. A preempting event is a message in such a conversation that is addressed to the digital life: in a private chat, any message from the other person; in a group, one that mentions or replies to the digital life. All other events steer at the boundary as before, including ordinary group messages and messages from other conversations. A busy group therefore cannot keep cancelling thought, and the digital life still decides whether to turn its attention elsewhere. A preempting message is no more an obligation to reply than any other message.

The earliest safe point depends on what the thought is doing. Preparation of a request, such as compaction, finishes and is kept, so the next thought need not repeat it. During a model call, the call is cancelled and its unfinished output discarded. Between the tool calls of a batch, sends to that conversation that have not started are skipped with a result that says why, and the message enters at the boundary. A tool that has started always finishes, so preemption never creates an unknown action outcome ([ADR-0008](0008-preserve-unknown-action-outcomes.md)).

A cancelled call ends the thought, but not as a failure. Completed turns stay in the working context and are saved, events that already entered count as perceived, events steered in but not yet entered return to pending, and there is no rollback or retry delay. Images seen and chat records read in the cancelled thought are not folded when it ends: the next thought decides again with them in view and folds them when it ends. A new thought then starts after the usual quiet window, so a burst of lines is read as one observation. A steady stream of messages could otherwise cancel every call, so after `limits.maxPreemptions` consecutive preemptions, counting cancelled calls and skipped sends alike, the next decision is carried out as made and the count starts again. Setting it to `0` turns preemption off. Administrative stops and timeouts keep their own cancellation, which still discards the whole thought.

A thought also ends after a batch of tool calls that were all social actions and all succeeded: sending a private or group message or a saved sticker, reacting with an emoji, or poking someone. Their success receipts stay in the working context and are read with the next observation, as ambient events are, but they no longer prompt a model call of their own. From 2026-10-28 to 2026-10-29, 217 of the 255 calls made only to read such receipts ended without any action. They spent about 33 minutes of model time, and an observation waited behind 51 of them. To send several messages, add a sticker, or note something down, the digital life makes those calls in the same batch, so it still decides when a thought ends by what it puts there. Another call still follows a failed or unknown outcome ([ADR-0008](0008-preserve-unknown-action-outcomes.md)) and a result the digital life needs, such as a read or the ID of a newly saved sticker. It also follows housekeeping such as describing a sticker or setting an activity, which often comes before a reply. Events that arrive during the batch steer in as usual, and the thought goes on for them.

This narrows the boundary rule above for preempting events and replaces "Ordinary events still do not cancel a model call made for thinking" from the revision of 2026-10-28. The single primary thinking process and continuous perception are unchanged. Pi offers only boundary steering and an abort that ends the run, and OpenCode's session inbox offers only steering and queueing. OpenClaw's `interrupt` queue mode aborts the active run and starts the newest message as a new turn on its persisted transcript, and room events never interrupt there. Preemption here follows that design on top of Pi's abort, with the working-context persistence of [ADR-0004](0004-persist-continuity-beyond-model-context.md) keeping completed turns. Checked 2026-10-29 against pi-agent-core 1.4.0, OpenCode `87a35fa`, and OpenClaw `20121545`.

Revision of 2026-11-02: a sticker saved and described in one call ([ADR-0010](0010-expose-native-snowluma-actions.md), revision of 2026-11-02) ends a thought as social actions do: a batch whose calls all succeeded, each a social action or such a save, ends it. What a save returned that the digital life needed was the sticker's ID, to describe it. From 2026-10-26 to 2026-11-02, 97 of 185 saves were followed by another call in the same thought, and only one of those sent the saved sticker with `send_custom_face`. A save without a description, one whose description failed or whose outcome is unknown, and a save of a sticker QQ already held, whose kept description the digital life may want to check, are still followed by another call.

Revision of 2026-11-06: primary working-context compaction now runs beside thoughts once the idle interval and `compaction.idleRatio` threshold are both reached. A foreground summary took 43 seconds during the afternoon's drawing conversation. The earlier rules also allowed an arriving event to cancel an idle summary only for the next thought to summarize the same history again at the same threshold. Cancelling that work no longer makes room for a prompt reply.

One background task captures a stable history prefix and summarizes it with its own cancellation, request accounting, and token meter. It generates summaries without executing tools or external actions. New events neither cancel it nor wait for it while the full input budget has room. When the summary is ready, a request boundary, thought completion, or idle completion may replace exactly the matching prefix. The current retained tail and all later exchanges remain, including completed tool calls and their receipts; a fresh complete runtime snapshot supplies the base for retained deltas. The live transcript is never replaced during a model call. The replacement and its provenance are saved atomically, without acknowledging any event on behalf of the background task.

At the hard input budget, a request waits for the existing task and uses its result if still applicable. If the task failed, its prefix no longer matches, or its reduction is insufficient, ordinary foreground pruning and compaction remain the fallback. A busy environment with no idle interval can still reach this fallback. Administrative pause, explicit deletion, context identity changes, and shutdown invalidate background work; plugin maintenance drains it. A failed or cancelled task never restores its old snapshot over newer conversation. The background task's call budget and traces are independent of the current thought, and an unfinished task is expendable on restart because the uncompressed context remains persisted.

This replaces the 2026-10-28 rule that new events cancel idle compaction and the 2026-10-29 soft-threshold check at the first primary request. Memory review, which has a separate disposable context and no idle compaction phase, retains its existing compaction policy. The single acting subject, pause semantics, provenance-aware deletion, and preservation of unknown action outcomes remain unchanged.
