# Draw apart from the thought and send drawings by their ID

The operator wanted the digital life to be able to draw. On 2026-11-02 the local CLIProxyAPI gateway, which already serves its model, answered `/v1/images/generations` for `gpt-image-2` and `gpt-image-2.5` through the operator's Codex subscription. Each request took 21 to 22 seconds and returned one PNG of about 1400×1100 pixels and 3 to 4 MB as `b64_json`. The gateway ignored the requested size, quality, and output format and reported quality `low` either way.

The digital life therefore has a `draw` tool outside the SnowLuma catalog, as it has web reading and search; this does not change [ADR-0010](0010-expose-native-snowluma-actions.md) for QQ operations. It takes a description and calls an OpenAI-compatible `/images/generations` endpoint the operator configures under `drawing`. Only the model and the description are sent, since a gateway may ignore the rest. The description is all the painter sees, so the tool asks for it in full.

Painting takes half a minute or more, and a thought holds the digital life's single attention ([ADR-0002](0002-single-attention-with-continuous-perception.md)): waiting in the tool would hold back every reply meanwhile. The tool returns at once with the drawing's ID, and the picture is painted apart from the thought. When it is done, a `drawing` event comes as an observation with the picture attached, ahead of images people sent, and starts or steers a thought like any other event. A drawing that fails comes back the same way with the endpoint's reason, such as a refusal by its safety system, and no picture. Drawings under way are kept in the store, so one a restart cut short is reported as such at the next start rather than awaited forever ([ADR-0007](0007-delayed-perception-and-explicit-recovery-gaps.md)).

The digital life sees a drawing before it decides what to do with it: send it, post it to Qzone, save it as a sticker, or keep it to itself. Its picture is kept as a file, and its ID, `drawing:<uuid>`, stands for it wherever an image file goes, such as the file of an image segment, an entry of `send_qzone_msg` images, or the file of `add_custom_face`. The picture is put in as `base64://` data, which SnowLuma accepts for media, only in what is sent: the action record keeps the ID ([ADR-0008](0008-preserve-unknown-action-outcomes.md)), and the picture's megabytes never pass through the model as text. An ID whose file is gone fails before anything is recorded or sent. Files older than memory retention are removed at start, since the events that name them are gone by then.

A drawing is the digital life's own work, so a drawing event is not evidence of what anyone else did and cannot alone support a habit or impression ([ADR-0012](0012-self-maintained-development-alongside-the-operator-persona.md)). Drawing is offered at life wakes among the online activities, with when the digital life last drew.

There is no limit on how often it draws. The endpoint's quota is the operator's to watch; whether to draw what someone asks for is the digital life's choice, as any [social request](../../GLOSSARY.md) is. Drawing from a reference image, through `/images/edits`, is left for later.
