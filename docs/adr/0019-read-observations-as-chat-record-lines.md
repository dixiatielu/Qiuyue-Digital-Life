# Read observations as chat-record lines

An observation used to show each event as an object: its full ID, an ISO time, the group, the actor, post, message, and sub type, the sender with card, nickname, role, sex, and age, the text, whether it was truncated, the message ID, and the message's segments, which for plain text repeat the text. A ten-character group message took about 140 tokens, of which the text was about 9. From 2026-11-02 13:45 to 17:30 the 508 observations brought 731 events in about 107,000 tokens of event objects, 210 per observation, and the working context keeps each of them until compaction ([ADR-0017](0017-tell-the-working-context-each-thing-once.md)).

An observation now shows its events in the line-per-item form the digital life already reads in `read_chat_record` and in a `rest_backlog` note ([ADR-0016](0016-hold-group-chat-while-resting.md)). The same 508 observations take about 46,000 tokens this way, 92 per observation. Events are grouped by chat, in the order each chat first appears, under a heading naming the group or person. Each line gives the local time, the event's `#xxxxxxxx` reference, the speaker, and the text with its segments written as the record writes them: mentions, replies with the message they answer, faces by name, stickers and images by summary. Reactions join the line of the message they react to when the observation shows it.

An observation is acted on, not only read, so its lines differ from the record's in what a thought needs at hand. Each person comes with their QQ number instead of a legend, each message with its `message_id` for replying, reacting, or recalling, and a reaction to a message the observation does not show with that message's `message_id`. Images are numbered as their pictures are labeled, and each label carries the image's URL, which saving it as a sticker or sending it on needs. A forwarded chat keeps its ID. Text runs as far as before, up to 2,000 characters by how many events share the observation, and a longer one says how many characters are left and to read them with `read_event`. A date is given only for events from another day. A notice the record has no form of its own for keeps its remaining fields, such as a changed group card. The program's own events, such as wakes, memory maintenance, revisions, perception gaps, and drawings, and pushes outside any chat, such as friend requests and connection events, each take a line with their kind and text; pushes and wakes keep their other fields, such as a friend request's flag.

What a line leaves out, such as a sender's role, an image's file name, a card's data, or a file's ID, stays in the stored event, and `read_event` with the reference shows all of it. A reference serves as an event ID wherever one is taken, as it already did for `read_event`, `view_event_image`, and `remember`. Nothing perceived is dropped ([ADR-0011](0011-perceive-all-snowluma-push-events.md)); a thought that needs a field the line leaves out spends one call to read it.

Writing the lines looks up a group's name, people's latest names, and the messages replies and reactions point at, now for every observation rather than only when a record is read. Without an index on the group or the actor each lookup scanned the events, about 65 ms apiece in the 2.9 GB store, so events are now indexed by group and time and by actor and time, and a message is looked up newest first.

The instructions do not change, so a deploy keeps the working context whose identity they help define. The observation's own first line says that times are +08:00 and that a reference is an event ID. Observations already in the working context keep the object form until compaction removes them.
