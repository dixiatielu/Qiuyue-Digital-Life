# Reload scoped plugins between thoughts

The operator wanted to add capabilities without editing the program or restarting the digital life. User plugins therefore declare a versioned interface from their own directories, while the host owns their tools, observation contributions, timers, background work and cleanup. They run as trusted local code; exposing the database and brain as a public interface would make independent upgrades and lifecycle control unreliable. Aurabot's scoped resources and whole-directory source snapshots informed the loader, but a failed candidate must leave the running version available.

This revises [ADR-0020](0020-a-management-page-apart-from-the-daemon.md): the management page asks the daemon to reload plugin settings and user code through a tracked control operation. Preparation has no SDK-managed external side effects. Dispatch then stops long enough for the current thought, parallel memory review, steering and affected background work to finish; perception continues saving events. New bindings become visible together and old tool references are revoked. A drain timeout retains the old instance and resumes its timers. Generations of working context change only when tool declarations or a plugin's declared context contract change, preserving memory and continuing state. Core configuration and built-in program code still take effect on restart.

Separate source snapshots refresh relative imports and are retained until cleanup for lazy imports. In-process Node modules have no reliable cache eviction, and arbitrary plugin code cannot be sandboxed or forcibly cancelled by this interface. The first version consequently uses explicit reload for trusted local plugins; workers would be the next step if frequent long-lived development or stronger fault isolation warrants their message-based interface.
